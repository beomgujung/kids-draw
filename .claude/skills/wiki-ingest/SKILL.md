# wiki-ingest

원자료를 위키 지식으로 컴파일한다. 규칙의 원본은 프로젝트 루트 `CLAUDE.md`의 "LLM Wiki" 섹션이다. 먼저 그것을 따른다.

## 0. 대상 정하기

- 인자가 있으면 해당 파일(들)을 대상으로 한다.
- 인자가 없으면 `raw/` 전체 목록과 `wiki/log.md`의 `ingest` 기록, `wiki/research/*.md` frontmatter의 `sources`를 비교해 **아직 반영되지 않은 원자료**를 찾는다. 여러 개면 목록을 보여주고 하나씩 처리한다.
- URL을 받았다면 내용을 가져와 `raw/YYYY-MM-DD-slug.md`로 저장한 뒤(원문 URL을 맨 위에 기록) 그 파일을 ingest한다. 그 외에는 `raw/`를 **절대 수정하지 않는다.**

## 1. 읽기

1. `wiki/index.md`와 `wiki/overview.md`를 읽어 현재 지식 상태를 파악한다.
2. 원자료를 끝까지 읽는다. 이미지는 직접 보고, PDF는 페이지 단위로 읽는다.
3. 사용자에게 핵심 요점 3~5개를 짧게 보고하고, 강조하거나 무시할 부분이 있는지 한 번 묻는다. (사용자가 "알아서"라고 했거나 배치 처리 중이면 생략)

## 2. 요약(source) 페이지 작성

`wiki/research/source-<slug>.md` 생성:

```markdown
---
title: <원자료 제목>
type: source
tags: [...]
sources: [raw/<파일>]
updated: <오늘 날짜>
---

# <제목>

- 원자료: `raw/<파일>` (저자/출처/날짜)
- 한 줄 요약:

## 핵심 내용
## kids-draw에 주는 시사점
## 관련 페이지
- [[...]]
```

"시사점"은 이 앱(유아 그리기·색칠 앱)의 기능/디자인/기술 결정에 어떤 의미가 있는지에 집중한다.

## 3. 기존 페이지에 통합 (핵심 단계)

원자료가 다루는 개념·기능·주제마다:

- 해당 페이지가 있으면(`product/`, `design/`, `tech/`, `research/` 종합 페이지) 새 정보를 **기존 서술에 녹여** 갱신하고 출처 링크를 단다. 단순히 맨 끝에 덧붙이지 않는다.
- 없으면 새 concept/entity 페이지를 만든다. 한 페이지는 한 주제.
- 기존 내용과 모순되면 `> ⚠️ 상충:` 블록으로 양측 출처와 함께 기록한다. 결정이 필요하면 사용자에게 알린다.
- 결정 사항(예: "브러시는 3종만 제공")이 도출되면 `wiki/decisions/NNNN-<slug>.md`에 ADR 초안(상태: 제안)을 만든다.
- 바뀐 결론이 프로젝트 전체에 중요하면 `wiki/overview.md`도 갱신한다.
- 수정한 모든 페이지의 frontmatter `updated`, `sources`를 갱신한다.

## 4. index.md 갱신

새 페이지는 해당 카테고리에 `- [[경로/파일명]] — 한 줄 요약` 형식으로 추가. 기존 항목 요약이 바뀌었으면 고친다.

## 5. log.md 기록 (append)

```
## [YYYY-MM-DD] ingest | <원자료 제목>
- 생성: [[...]], [[...]]
- 갱신: [[...]], [[...]]
- 요점: <한두 줄>
```

## 6. 보고

사용자에게 짧게: 생성/갱신 페이지 목록, 발견한 상충·결정 필요 사항, 다음에 읽으면 좋을 자료 제안.

## 체크리스트

- [ ] raw/ 파일을 수정하지 않았다
- [ ] 모든 새 페이지에 frontmatter가 있다
- [ ] 모든 새 페이지가 index.md에 있고, 최소 1개 다른 페이지에서 링크된다
- [ ] 사실 주장마다 출처 링크가 있다
- [ ] log.md에 항목을 추가했다
